# i18n Guide for Astrowind

## Overview

Astrowind uses a hybrid i18n system:

- **Astro native routing** for locale‑prefixed URLs (`/[locale]/...`)
- **Wuchale** in "Full Automation" for compile‑time string auto extraction and translation (`.po` files). No explicit marking or special syntax required in source code.
- **Content collections** for localized pages (`src/data/pages/[locale]/`) and blog posts (`src/data/post/[locale]/`)
- **Virtual module** `astrowind:config` for configuration

## Key Files

- `src/config.yaml` – i18n settings (locales, defaultLocale, localeNames)
- `astro.config.ts` – Astro i18n routing configuration
- `wuchale.config.js` – Wuchale extraction configuration
- `src/utils/i18n.ts` – Core i18n utilities (`getPathWithoutLocale`, `getStaticPathsForLocale`)
- `src/utils/permalinks.ts` – Permalink generation with locale support
- `src/middleware.js` – Locale injection for Wuchale runtime
- `src/locales/` – Auto‑generated wuchale files. Do not edit manually (files get overwritten)

## Core Principle: Explicit Locale Propagation

**`Astro.currentLocale` is only available in `.astro` files.** Pass it explicitly to utility functions.

```astro
---
// In .astro files - Astro.currentLocale IS available
const locale = Astro.currentLocale;
const headerData = getHeaderData(locale);
---

<Header {...headerData} currentLocale={locale} />
```

## Rules for Developers

### 1. Use `getPermalink()` for All Internal Links

`getPermalink()` handles:
- Stripping existing locale prefixes from paths
- Adding new locale prefix
- Respecting `SITE.trailingSlash` config

```astro
---
import { getPermalink } from '~/utils/permalinks';
const locale = Astro.currentLocale;
---

<!-- With explicit locale -->
<a href={getPermalink('/about', 'page', locale)}>About</a>

<!-- For language switcher - pass current path with new locale -->
<a href={getPermalink(Astro.url.pathname, 'page', 'es')}>Español</a>
```

### 2. Never Hardcode Locale Prefixes

**Wrong**: `<a href="/en/blog">`
**Right**: `<a href={getPermalink('blog', 'blog', locale)}>`

### 3. Use `Astro.currentLocale` Directly in .astro Files

```astro
---
const locale = Astro.currentLocale ?? I18N.defaultLocale;
---

<p>Current locale: {locale}</p>
```

### 4. Pass Locale to Components

Components that need locale (like Header) should receive it as a prop:

```astro
<!-- In Layout -->
const locale = Astro.currentLocale;
---
<Header currentLocale={locale} ... />
```

### 5. Adding a New Locale

1. Add locale code to `src/config.yaml` `i18n.locales`.
2. Create `src/data/pages/[new‑locale]/` directory for regular pages.
3. If blog is enabled, also create `src/data/post/[new‑locale]/` for blog posts.
4. Run `bun run dev` – Wuchale will generate `.po` files.
5. Translate strings (or use Gemini AI auto‑translation by setting `i18n.ai.geminiApiKey` in config).

### 6. Pluralization and Advanced Formatting

Wuchale supports plural forms (`plural`) and gender selection (`select`). Use the `t` function directly in components:

```astro
---
import { t } from 'wuchale:main';
---

<p>{t('You have {count, plural, one {# item} other {# items}}', { count: items.length })}</p>
```

Date and number formatting should use `Intl` with the current locale:

```astro
---
const locale = Astro.currentLocale ?? I18N.defaultLocale;
const formatter = new Intl.DateTimeFormat(locale, { dateStyle: 'full' });
---

<p>{formatter.format(new Date())}</p>
```

### 7. Fallback Strategy

- **UI strings**: Wuchale automatically falls back to source locale (English) for missing translations.
- **Dynamic pages & blog posts**: No automatic fallback; 404 is intentional to enforce translation completeness.
- **Browser language detection**: Root redirect (`/`) uses client-side JavaScript to detect browser language, with noscript fallback to default locale.

### 8. Production Readiness

- **Missing translations**: Fallback to English (source locale) with console warnings in development.
- **Cache headers**: Configure your CDN to vary cache by `Accept‑Language` and `locale` path segment.
- **SEO**: `hreflang` tags are auto‑generated in `Layout.astro` for all pages.
- **Sitemap**: All locale variants are included automatically via `@astrojs/sitemap`.

### 9. Troubleshooting

- **Missing locale prefix**: Ensure you're passing locale explicitly to `getPermalink()`.
- **Wrong locale in links**: Check that `currentLocale` prop is passed from parent layout.
- **Wuchale not extracting**: Check `wuchale.config.js` heuristic.
- **Empty strings for translations**: Verify `.po` files are up‑to‑date; run `bun run dev` to regenerate.

## API Reference

### `getPermalink(slug, type?, locale?)`

Generates locale-aware URLs.

```typescript
getPermalink('/about', 'page', 'es') // → '/es/about'
getPermalink(Astro.url.pathname, 'page', 'fr') // → '/fr/current-path'
```

### `getHomePermalink(locale?)`

Shortcut for home page.

```typescript
getHomePermalink('es') // → '/es'
```

### `getBlogPermalink(locale?)`

Shortcut for blog index.

```typescript
getBlogPermalink('es') // → '/es/blog'
```

### `getPathWithoutLocale(pathname)`

Strips locale prefix from a path. Used internally by `getPermalink()`.

```typescript
getPathWithoutLocale('/en/about') // → '/about'
```

### `getStaticPathsForLocale()`

For `getStaticPaths` in `[locale]` pages.

```astro
export const getStaticPaths = getStaticPathsForLocale;
```
