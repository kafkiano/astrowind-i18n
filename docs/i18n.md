# i18n Guide for Astrowind

## Overview

Astrowind uses a hybrid i18n system:

- **Astro native routing** for locale‑prefixed URLs (`/[locale]/...`)
- **Wuchale** for compile‑time string extraction and translation (`.po` files)
- **Content collections** for localized pages (`src/data/pages/[locale]/`) and blog posts (`src/data/post/[locale]/`)
- **Virtual module** `astrowind:config` for configuration

## Key Files

- `src/config.yaml` – i18n settings (locales, defaultLocale, localeNames)
- `astro.config.ts` – Astro i18n routing configuration
- `wuchale.config.js` – Wuchale extraction configuration
- `src/utils/i18n.ts` – Core i18n utilities (use `getCurrentLocale()`)
- `src/utils/permalinks.ts` – Permalink generation (auto‑detects locale)
- `src/middleware.js` – Locale injection for Wuchale runtime
- `src/locales/` – Auto‑generated files (`.po` translations and `data.js` compiled strings). Do not edit manually except for translations within `.po` files.

## Rules for Developers

### 1. Use `getPermalink()` Without Explicit Locale

**Wrong**: `getPermalink(post.permalink, 'post', currentLocale)`
**Right**: `getPermalink(post.permalink, 'post')` – locale auto‑detected

### 2. Never Hardcode Locale Prefixes

**Wrong**: `<a href="/en/blog">`
**Right**: `<a href={getPermalink('blog', 'blog')}>`

### 3. Use `getCurrentLocale()` for Display

```astro
---
import { getCurrentLocale } from '~/utils/i18n';
const locale = getCurrentLocale();
---

<p>Current locale: {locale}</p>
```

### 4. Adding a New Locale

1. Add locale code to `src/config.yaml` `i18n.locales`.
2. Create `src/data/pages/[new‑locale]/` directory for regular pages.
3. If blog is enabled, also create `src/data/post/[new‑locale]/` for blog posts.
4. Run `bun run dev` – Wuchale will generate `.po` files.
5. Translate strings (or use Gemini AI auto‑translation by setting `i18n.ai.geminiApiKey` in config).

### 5. Pluralization and Advanced Formatting

Wuchale supports plural forms (`plural`) and gender selection (`select`). Use the `t` function directly in components:

```astro
---
import { t } from 'wuchale:main';
---

<p>{t('You have {count, plural, one {# item} other {# items}}', { count: items.length })}</p>
```

Date and number formatting should use `Intl` with the current locale:

```astro
---
import { getCurrentLocale } from '~/utils/i18n';
const locale = getCurrentLocale();
const formatter = new Intl.DateTimeFormat(locale, { dateStyle: 'full' });
---

<p>{formatter.format(new Date())}</p>
```

### 5. Fallback Strategy

- **UI strings**: Wuchale automatically falls back to source locale (English) for missing translations (already works).
- **Dynamic pages & blog posts**: No automatic fallback; 404 is intentional to enforce translation completeness.
- **Browser language detection**: Root redirect respects `Accept‑Language` header via client‑side JavaScript, with noscript fallback to default locale.

### 6. Production Readiness

- **Missing translations**: Fallback to English (source locale) with console warnings in development.
- **Cache headers**: Configure your CDN to vary cache by `Accept‑Language` and `locale` path segment.
- **SEO**: `hreflang` tags are auto‑generated; verify via `CommonMeta.astro`.
- **Sitemap**: All locale variants are included automatically via `@astrojs/sitemap`.

### 7. Troubleshooting

- **Missing locale prefix**: Ensure you're not passing `undefined` as locale (use auto‑detect).
- **"Astro is not defined"**: Already fixed in `getCurrentLocale()`.
- **Wuchale not extracting**: Check `wuchale.config.js` heuristic.
- **Empty strings for translations**: Verify `.po` files are up‑to‑date; run `bun run dev` to regenerate.

## Migration from Old Patterns

Replace `getPermalink(..., ..., locale)` with `getPermalink(...)`.
Remove `getCurrentLocale()` imports where only used for permalinks.
