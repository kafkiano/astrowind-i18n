# i18n Guide for Astrowind

## Overview

Astrowind uses a custom i18n system (`src/i18n/`, ~1500 lines) with zero external framework dependencies. The system was built as a replacement for Wuchale after structural issues with Astro's scope hoisting prevented correct runtime injection.

### Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                     astro:config:setup                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────────┐  │
│  │ Extract   │→ │ Prune +  │→ │   Sync   │→ │  Translate │  │
│  │ strings   │  │  Merge   │  │ catalogs │  │  (AI API)  │  │
│  │ .astro    │  │ source   │  │ target   │  │ untrans-   │  │
│  │ files     │  │ catalog  │  │ catalogs │  │ lated ""   │  │
│  └──────────┘  └──────────┘  └──────────┘  └────────────┘  │
│                                                              │
│  ┌──────────────────────┐  ┌──────────────────────────────┐ │
│  │ Translate markdown   │  │ Clean up orphans + stale     │ │
│  │ src/data/{post,pages}│  │ removed-locale artifacts     │ │
│  └──────────────────────┘  └──────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     astro:build:done                         │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ Post-process HTML: walk dist/ → full-string match    │   │
│  │ source-locale text → replace with catalog translation│   │
│  │ Script tags excluded. Entity decoding normalized.    │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### Key Files

| File | Role |
|---|---|
| `src/config.yaml` | i18n settings: locales, defaultLocale, AI provider, API keys |
| `src/i18n/catalog.ts` | Load/save JSON catalogs (`src/locales/{locale}.json`) |
| `src/i18n/config.ts` | Single source of truth for i18n configuration (reads `config.yaml` + env vars) |
| `src/i18n/extract.ts` | AST-based string extraction from `.astro` files (markup, attributes, expression props) |
| `src/i18n/heuristic.ts` | Classifies extracted strings as translatable or code/URL/CSS |
| `src/i18n/integration.ts` | Orchestration: extract → prune → sync → translate → cleanup + post-process |
| `src/i18n/manifest.ts` | Content-addressed manifest (`.i18n-manifest.json`) for incremental translation |
| `src/i18n/markdown.ts` | Markdown content translation + orphan cleanup |
| `src/i18n/postprocess.ts` | DOM-based HTML post-processing: replaces source-locale text in `dist/` |
| `src/i18n/provider.ts` | Gemini (raw fetch REST API) + DeepL (deepl-node SDK) implementations |
| `src/locales/{locale}.json` | JSON catalogs: `{ "source string": "translated string" }` |
| `src/locales/.i18n-manifest.json` | Translation manifest tracking SHA-256 hashes |

## Configuration

All i18n settings live in `src/config.yaml` under the `i18n` key:

```yaml
i18n:
  language: en
  textDirection: ltr           # 'ltr' or 'rtl'
  locales: ['en', 'es', 'fr', 'de']   # All locale codes
  defaultLocale: en             # Source language for .astro/.md files
  localeNames:
    en: English
    es: Español
    fr: Français
    de: Deutsch
  ai:
    provider: 'deepl'          # 'gemini' or 'deepl'
    geminiApiKey: null         # or your key string
    # deeplApiKey: null        # or via DEEPL_API_KEY env var
    # model: 'gemini-2.5-flash' # only for Gemini, only affects markdown body
```

**Environment variable overrides:**
- `GEMINI_API_KEY` / `DEEPL_API_KEY` — API key (takes precedence over config.yaml)
- `I18N_PROVIDER` — override provider (`'gemini'` or `'deepl'`)
- `I18N_MODEL` — override Gemini model

**No API key?** The build succeeds normally — all pages show source-locale text. Translation is simply skipped. The log shows: `[i18n] Translation provider unavailable`.

## How It Works

### UI Strings (`.astro` files)

1. **Extraction**: At build time, the integration walks all `.astro` files. `@astrojs/compiler` parses each into an AST. Text nodes, quoted attributes, and **expression prop values** (parsed with acorn) are collected and classified by a heuristic: UI prose is translatable; code, URLs, CSS classes, and script contents are excluded.

2. **Prune + Merge**: Extracted strings are compared against the source locale catalog (`{defaultLocale}.json`). New strings are added with empty value `""`. Dead strings (in the catalog but not found in any `.astro` file) are removed from all locale catalogs.

3. **Sync**: New keys are propagated to target locale catalogs with value `""`. Dead keys are removed.

4. **Translation**: Strings with `""` values in target catalogs are sent to the AI provider (batched, with retries). A content-addressed manifest (SHA-256 of the source catalog JSON) skips translation when nothing changed.

5. **Post-process**: After Astro builds all HTML, the integration walks `dist/` and replaces source-locale text segments with catalog translations using **full-string matching** (no substring tokenization — prevents mixed-language corruption like `"Home"` matching inside `"Homepage"` → `"Iniciopage"`).

### Markdown Content (`.md`/`.mdx` files)

1. **Detection**: The integration globs `src/data/{post,pages}/{defaultLocale}/**/*.md{,x}`. Each file's SHA-256 hash is compared against the manifest.

2. **Translation**: New or changed files are translated:
   - **Frontmatter** (`title`, `excerpt`, `description`, `group`): translated line-by-line via `translateBatch`.
   - **Body**: translated as a single block via `translateText` with a "preserve all formatting" prompt (critical for multi-line markdown).
   - **Category is NOT translated** — translating categories changes slugs and causes 404s.

3. **Output**: Translated files are written to `src/data/{type}/{locale}/` directories.

4. **Orphan cleanup**: After translation, target locale dirs are scanned. Files whose source no longer exists are deleted automatically. Manifest entries are cleaned up.

### Manifest (`src/locales/.i18n-manifest.json`)

Content-addressed (SHA-256), not mtime-based. Survives git clones, branch switches, and mtime resets:

```json
{
  "markdown": {
    "src/data/post/en/foo.md": "abc123...",
    "src/data/pages/en/privacy.md": "def456..."
  },
  "catalogs": {
    "en": "789abc..."
  }
}
```

## User Story Reference

| Action | Behavior | Notes |
|---|---|---|
| **New `.astro` string** | Extracted → added to source catalog → synced → AI translates | No manual steps needed |
| **New `.md` file** | Manifest detects hash mismatch → translated to all target locales | Frontmatter + body translated separately |
| **Modify `.astro` string** | Old key pruned, new key translated (same flow) | Old translations lost if key changes |
| **Modify `.md` file** | Manifest hash change triggers re-translation | Manual edits in target files are **overwritten** when source changes |
| **Delete `.astro` string** | Automatically pruned from all catalogs | Pruning runs automatically during build |
| **Delete `.md` source file** | Orphan translations in all target dirs auto-deleted | Manifest entries cleaned up |
| **Manual translation edit (catalog)** | **Never overwritten** by AI (non-empty values are preserved) | Safe to fix bad AI translations |
| **Manual translation edit (markdown)** | Survives until source `.md` changes | Lost on source update — re-translated from English |
| **Add locale** | Add to `locales` array in config → build → auto-translate everything | No manual dir creation needed |
| **Remove locale** | Remove from `locales` → build warns about stale dirs/files | Manual cleanup recommended |
| **No API key** | Graceful degradation — build succeeds, source text shown | Provider logs "unavailable" warning |
| **Change source locale** (cold start) | Set `defaultLocale` before first build | All extraction/sync/post-processing adapts |

## Core Principle: Explicit Locale Propagation

**`Astro.currentLocale` is only available in `.astro` files.** Pass it explicitly to utility functions and components.

```astro
---
// In .astro files - Astro.currentLocale IS available
const locale = Astro.currentLocale;
const headerData = getHeaderData(locale);
---

<Header {...headerData} currentLocale={locale} />
```

## Rules for Developers

### 1. Use `getPermalink()` for All Internal Links

`getPermalink()` handles:
- Stripping existing locale prefixes from paths
- Adding new locale prefix
- Respecting `SITE.trailingSlash` config

```astro
---
import { getPermalink } from '~/utils/permalinks';
const locale = Astro.currentLocale;
---

<!-- With explicit locale -->
<a href={getPermalink('/about', 'page', locale)}>About</a>

<!-- For language switcher - pass current path with new locale -->
<a href={getPermalink(Astro.url.pathname, 'page', 'es')}>Español</a>
```

### 2. Never Hardcode Locale Prefixes

**Wrong**: `<a href="/en/blog">`
**Right**: `<a href={getPermalink('blog', 'blog', locale)}>`

### 3. Pass Locale to Components

Components that need locale (like Header) should receive it as a prop:

```astro
<!-- In Layout -->
const locale = Astro.currentLocale;
---
<Header currentLocale={locale} ... />
```

### 4. Adding a New Locale

1. Add locale code to `src/config.yaml` `i18n.locales` array.
2. Add locale name to `i18n.localeNames`.
3. Run `bun run build` — the system generates the catalog and auto-translates all content.

No need to manually create directories or files. The system handles everything.

### 5. Removing a Locale

1. Remove locale code from `src/config.yaml` `i18n.locales` array.
2. Run `bun run build` — warnings will list stale directories and files.
3. Manually delete the listed stale artifacts.

Auto-deletion is not performed for removed locales to prevent accidental data loss.

### 6. Manual Translation Overrides

**For UI strings (catalog):** Edit the value directly in `src/locales/{locale}.json`. Non-empty values are never overwritten by AI translation. Safe to commit.

**For markdown content:** Edit the translated `.md` file in the target locale directory. Your edit survives until the source (default locale) file is modified. When the source changes, the entire file is re-translated from scratch — manual edits are lost. If you need long-term manual translations for markdown, maintain them in the source locale instead.

### 7. Fallback Strategy

- **UI strings**: If a translation is missing (`""` in catalog), the source-locale text is shown until the next build translates it.
- **Markdown content**: If a source file hasn't been translated yet (provider unavailable or build interrupted), no target-locale file exists. Astro's content collection returns only files that exist — the post simply won't appear in that locale.
- **404 for untranslated pages**: Intentional. No automatic fallback to source locale for dynamic pages and blog posts.

### 8. SEO & Routing

- **hreflang tags**: Auto-generated in `src/layouts/Layout.astro` for all pages.
- **Sitemap**: All locale variants included automatically via `@astrojs/sitemap`.
- **Routing**: All routes are locale-prefixed (`/[locale]/...`). `prefixDefaultLocale: true`, `redirectToDefaultLocale: false`.

## API Reference

### Permalink Functions (`src/utils/permalinks.ts`)

```typescript
getPermalink('/about', 'page', 'es')     // → '/es/about'
getHomePermalink('es')                    // → '/es'
getBlogPermalink('es')                    // → '/es/blog'
getCanonical('/about', 'page', 'es')     // → 'https://example.com/es/about'
```

### `getStaticPathsForLocale()`

For `getStaticPaths` in `[locale]` pages:

```astro
export const getStaticPaths = getStaticPathsForLocale;
```

### `getHeaderData(locale)` / `getFooterData(locale)`

Auto-scanned navigation data for header and footer (`src/utils/auto-navigation.ts`).

## Troubleshooting

### Translation not happening

1. Check API key is set (env var or config.yaml).
2. Check provider is specified (`i18n.ai.provider`).
3. Look for `[i18n] Translation provider unavailable` in build output.
4. Verify strings have `""` value in target catalogs — non-empty values are never re-translated.
5. Check manifest hasn't marked catalogs as "already translated" — delete `src/locales/.i18n-manifest.json` to force full re-translation.

### Missing locale prefix in links

Use `getPermalink()` for all internal links. Never hardcode locale prefixes.

### Wrong locale in rendered output

Ensure `Astro.currentLocale` is passed explicitly to components. It's only available in `.astro` files, not in `.ts` utilities.

### Orphan translated files not cleaned up

Run a full build (`bun run build`). Orphan cleanup runs automatically during the integration step. If orphans persist, check that source files were actually deleted (not just emptied).

### Dead catalog strings not removed

Catalog pruning runs automatically during build — dead strings are removed from all locale catalogs when they no longer appear in any `.astro` file.

### Mixed-language corruption in output

This is prevented by full-string matching in the post-processor. If you see corruption, it may be from the old Wuchale system — delete `dist/` and rebuild from scratch.

### Changing source/default locale

Set `i18n.defaultLocale` in `config.yaml` **before the first build**. The system uses this as the source language for extraction, sync, and post-processing. Changing it after content exists requires manual migration of catalog files and markdown directories.

### Adding back a previously removed locale

Add locale to `locales` array and rebuild. The catalog will be regenerated and all content re-translated. Previously translated files in `src/data/` that weren't manually deleted will have their translations overwritten by the fresh AI translation.
